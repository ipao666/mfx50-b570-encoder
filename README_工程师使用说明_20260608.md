## 3. 编译

在 Linux/B570 机器上：

```bash
cd /path/to/source
cmake -S . -B build -DMFX50RT_BUILD_FFMPEG_DEMOS=OFF
cmake --build build -j$(nproc)
```

主要产物：

```text
build/libmfx50rt.so
build/libmfx50_realtime.so
build/libmfx50_encoder.so
build/libmfx50_policy.so
build/mfx50_split_file_transcode
build/mfx50_encoder_minimal_demo
build/simple_transcode
```

打完整 B570 SDK 包：

```bash
cd /path/to/source
chmod +x packaging/make_b570_binary_sdk.sh
MFX50RT_SDK_VERSION=1.0.4-b570-resolutionfix-20260608 \
MFX50RT_DIST_DIR=/tmp/mfx50_dist \
./packaging/make_b570_binary_sdk.sh
```

## 4. 运行环境检查

B570 建议环境：

```text
Ubuntu 原生 Linux x86_64
Intel Media Driver iHD
oneVPL dispatcher + libmfx-gen
VAAPI / libva / libva-drm
/dev/dri/renderD128 或 /dev/dri/renderD129 可访问
用户在 render、video 组
```

常用检查命令：

```bash
vainfo --display drm --device /dev/dri/renderD129
vpl-inspect
ldconfig -p | grep -E 'libvpl|libmfx-gen'
ls -l /dev/dri
```

如果 `vainfo` 能看到 B570，但 `vpl-inspect` 显示没有 implementation，通常是 oneVPL GPU runtime 或 `libmfx-gen1.2` 没装好。

## 5. 45 路 B570 算法路径

推荐使用：

```text
examples/b570_fastpath/run_45_from_h264_dir.sh
examples/b570_fastpath/run_45_from_mp4_dir.sh
```

### 5.1 输入 H.264 Annex-B 裸码流

输入目录里放 45 个 `.h264` 或 `.264` 文件：

```bash
cd /path/to/sdk_or_source
export SAMPLE_MULTI_TRANSCODE=$PWD/bin/sample_multi_transcode_b570

examples/b570_fastpath/run_45_from_h264_dir.sh \
  /data/45_h264 \
  /tmp/b570_45_output \
  18000 \
  45
```

参数：

```text
/data/45_h264        输入目录，必须有 45 个 H.264 Annex-B 文件
/tmp/b570_45_output  输出目录
18000                每路最多处理帧数，30fps 下约 10 分钟
45                   路数
```

脚本默认编码参数：

```text
device    = /dev/dri/renderD129
usage     = veryfast
async     = 2
memtype   = video
gpucopy   = on
codec     = HEVC/H.265 输出
rate mode = CQP
QPI/QPP/QPB = 36/38/48
GOP_SIZE = 300
DIST = 4
FPS = 30
AdaptiveI = on
ScenarioInfo = 6
ContentInfo = 3
AdaptiveCQM = on
extmbqp = on
```

算法环境默认值：

```bash
MFX50RT_SAMPLE_HYBRIDTSRQ=1
MFX50RT_SAMPLE_HYBRIDTSRQ_ROI_ONLY=1
MFX50RT_SAMPLE_HYBRIDTSRQ_DISABLE_FRAME_QP=1
MFX50RT_SAMPLE_DAYNIGHT_ADAPTIVE_QP=0
MFX50RT_SAMPLE_HYBRIDTSRQ_HEAVY_INTERVAL=5
MFX50RT_SAMPLE_MBQP_REUSE_INTERVAL=30
MFX50RT_SAMPLE_ROI_ANALYZE_INTERVAL=30
MFX50RT_SAMPLE_DISABLE_ROI_FROM_MBQP=1
MFX50RT_SAMPLE_ROI_DELTA_QP=-4
MFX50RT_SAMPLE_PLATE_ROI_DELTA_QP=-12
MFX50RT_SAMPLE_PLATE_ROI_MARGIN=24
MFX50RT_SAMPLE_MBQP_SAFE_MAX=38
```

含义：基础帧 QP 使用 `36/38/48`，启用 ROI/MBQP 局部保护；默认不启用全局逐帧 QP 大幅波动。

### 5.2 输入 H.264 MP4

如果输入是 45 个 H.264 MP4 文件：

```bash
examples/b570_fastpath/run_45_from_mp4_dir.sh \
  /data/45_mp4 \
  /tmp/b570_45_output \
  18000 \
  45
```

该脚本会先用 FFmpeg 把 MP4 中的视频流拆成 H.264 Annex-B，再调用 `run_45_from_h264_dir.sh`，最后把输出 H.265 重新封成 MP4。

注意：这个脚本默认只接受 H.264 MP4。检查输入：

```bash
ffprobe -v error -select_streams v:0 \
  -show_entries stream=codec_name,width,height,r_frame_rate \
  -of default=nw=1 input.mp4
```

## 6. split decoder / encoder demo

文件：

```text
tools/mfx50_split_file_transcode.cpp
```

作用：演示拆分后的 API 怎么串起来，不代表 45 路算法效果。

流程：

```text
H.264/H.265 Annex-B 文件
  -> mfx50_decoder_push_packet()
  -> mfx50_decoder_poll_surface()
  -> oneVPL NV12 GPU surface
  -> mfx50_encoder_push_surface()
  -> mfx50_encoder_poll_packet()
  -> HEVC/H.265 输出文件
```

命令：

```bash
MFX50_DEVICE_PATH=/dev/dri/renderD129 \
LD_LIBRARY_PATH=. \
./mfx50_split_file_transcode \
  input.hevc \
  output.hevc \
  h265 \
  25 \
  30 \
  32
```

参数：

```text
input.hevc   输入 H.265/H.264 Annex-B 裸码流
output.hevc  输出 H.265/HEVC Annex-B 裸码流
h265         输入 codec，可填 h265 或 h264
25           fps
30           gop
32           QP，demo 中会设置 qpi/qpp/qpb = 32/32/32
```

这个 demo 用固定 QP/GOP，只用于验证：

```text
device -> decoder -> NV12 GPU surface -> encoder
```

## 7. split codec 主要函数

### 7.1 Device

头文件：

```text

```

主要函数：

```c
MFX50_Status mfx50_device_default_config(MFX50_DeviceConfig* config);
MFX50_Status mfx50_device_create(const MFX50_DeviceConfig* config,
                                 MFX50_Device** out_device);
const char* mfx50_device_get_last_error(MFX50_Device* device);
void mfx50_device_destroy(MFX50_Device* device);
```

关键参数：

```text
device_path              /dev/dri/renderD129 或 /dev/dri/renderD128
device_index             设备序号
interop_type             AUTO / VAAPI / ONEVPL
external_va_display      外部 VA Display，可选
external_mfx_session     外部 oneVPL session，可选
require_zero_copy        要求零拷贝
```

Device 是 Decoder 和 Encoder 的共同父对象，用于保证同一块 B570、同一个 VA/oneVPL 上下文。

## 9. 常见问题

### 9.1 `MFXCreateSession failed: MFX_ERR_NOT_FOUND`

通常不是 RTSP URL 或 codec 参数错，而是 oneVPL dispatcher 没找到对应 GPU runtime。检查：

```bash
vpl-inspect
ldconfig -p | grep -E 'libvpl|libmfx-gen'
```

B570 上需要 `libmfx-gen1.2`、`libvpl2`、Intel Media Driver。

### 9.2 2304x1296 编码失败

本版已修复 `MFX_ERR_NOT_ENOUGH_BUFFER(-5)` 处理。旧版遇到大分辨率首帧输出 buffer 不够时会直接失败；新版会扩容 bitstream buffer 后重试。

相关说明：

```text
docs/MFX50_ENCODER_RESOLUTION_BUFFER_FIX_20260608.md
```

### 9.3 是否需要手动输入 QP/GOP

45 路脚本不需要手动输入 QP/GOP，默认使用：

```text
QPI/QPP/QPB = 36/38/48
GOP_SIZE = 300
DIST = 4
```

需要覆盖时可以用环境变量：

```bash
QPI=34 QPP=36 QPB=42 GOP_SIZE=300 \
examples/b570_fastpath/run_45_from_h264_dir.sh /data/45_h264 /tmp/out 18000 45
```
